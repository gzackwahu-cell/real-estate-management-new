# Real Estate Management

> **Status: foundation only.** No application features are implemented yet. This
> repository contains a clean, deployment-ready starting point for a cloud-based
> real estate management application.

## Stack

| Concern | Choice |
| --- | --- |
| Language | TypeScript |
| Framework | Next.js 16 (App Router, Turbopack) |
| Hosting | Vercel (deploy from GitHub) |
| Database | Supabase PostgreSQL |
| Authentication | Supabase Auth (role-based access control to be added) |
| File storage | Supabase Storage |
| Database access | Official `@supabase/supabase-js` client (no ORM for now) |
| Styling | Tailwind CSS v4 + shadcn/ui (Radix base, Lucide icons) |
| Validation | Zod |
| Code quality | ESLint + TypeScript compiler checks |

## Prerequisites

- Node.js **20.9+** (this machine uses v22.16.0)
- npm
- Git
- A [Supabase](https://supabase.com) account
- A [GitHub](https://github.com) account
- A [Vercel](https://vercel.com) account

## Local setup

1. Install dependencies:

   ```bash
   npm install
   ```

2. Create your local environment file:

   ```bash
   cp .env.example .env.local
   ```

3. Open `.env.local` and paste the values from your Supabase project:
   **Project Settings → API**. Never commit this file.

4. Start the development server:

   ```bash
   npm run dev
   ```

5. Open [http://localhost:3000](http://localhost:3000).

## Environment variables

| Variable | Where it is used | Rule |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Browser + server | Public project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Browser + server | Public key; data safety comes from RLS policies |
| `SUPABASE_SERVICE_ROLE_KEY` | Server only | **Never** prefix with `NEXT_PUBLIC_`, never use in client code |
| `NEXT_PUBLIC_STORAGE_BUCKET` | Browser + server | Name of the Supabase Storage bucket for uploads |

`.env*` files are ignored by Git. Only `.env.example` (with empty values) is
committed. On Vercel, add the same variables in **Project → Settings →
Environment Variables**.

## Security rules

1. Secrets live only in `.env.local` (local) and Vercel environment variables.
2. The anon key may be public; **Row Level Security** must protect the data.
3. The service role key stays on the server and bypasses RLS — treat it like a
   password.
4. Uploaded files go to Supabase Storage, never to the local filesystem.

## Deploy to Vercel

1. Create a GitHub repository and push this folder to the `main` branch.
2. In Vercel, choose **Add New → Project** and import that repository.
3. Vercel detects Next.js automatically; no `vercel.json` is required.
4. Add the environment variables listed above for Production (and Preview if
   you want preview deployments to use Supabase).
5. Click **Deploy**. Every future push to GitHub creates a new deployment.
